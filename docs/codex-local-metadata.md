# Codex local model evidence

`account/usage/read` supplies account daily token buckets. The installed cloud CLI's generated experimental response schema also has optional `threadUsage.groups` (models and tokens for an explicitly requested thread), but no calendar-month per-model action counts or dated model breakdown. Tokenlight does not turn thread totals or a configured default model into monthly preference evidence. The bundled Mac CLI is an LFS pointer in this checkout; no live account response was fetched. The cloud schema is retained in `review/codex-usage-response-schema.json` and is evidence of this CLI version, not a promise about all installed versions.

`codex-local.mjs` samples `CODEX_HOME` (or `~/.codex`) `sessions/` and `archived_sessions/` read-only. It follows directories at most five levels deep and does not traverse symlinks. Each scan caps directory entries at 4,000, JSONL files at 256, bytes at 16 MiB total / 4 MiB per file, JSONL records at 20,000 and a line at 256 KiB. It discovers the selected month’s standard year/month directories first, then other candidates within the entry budget. Candidates matching the month sort first, then recently modified sessions (including older continued sessions). Each remaining candidate receives a fair share of the remaining byte budget (still at most 4 MiB per file), so four large files cannot exhaust all 16 MiB ahead of other candidates. Large files split their read budget between a prefix and a tail; contexts and cumulative baselines reset across the gap. A tail without its own model context stays unattributed. Stores beyond the discovery budget can still omit active older sessions. This is deliberate bounded sampling, not a complete index. Caps and metadata gaps are explicit. A five-minute in-memory cache shares concurrent scans and retains at most four sanitized root/month results. It never writes Codex user data. There is no persistent transcript index. On restart, the first scan is bounded again.

Only `turn_context.model` and `turn_id`, `session_meta.id` / internal-origin markers, event timestamps and validated numerical token counters are inspected for attribution. Prompts, answers, tool contents, account identity and credentials are neither returned nor cached. Session/turn identities and event fingerprints are hashed and used only during a scan. Returned state contains model identity, numerical counters, scan counts and fixed coverage notes.

A local active turn means a distinct session/turn with positive attributable usage in the UTC month. Per-model counts count that turn once per observed model; a switched turn can belong to multiple models. They are **not** replies, API requests or account-wide counts. Missing logs produce unknown counts, not a zero-use claim. Local coverage is always partial, including other devices and cloud sessions. Internal `codex-auto-review`, synthetic and unattributed model contexts cannot establish preference.

Token counts use disjoint uncached input, cached input and output; reasoning is already part of output. Valid cumulative snapshots dedupe repeated usage events and copied session files. Differences establish new usage; if a cumulative jump differs from `last_token_usage`, only the known last generation is attributed and a gap is flagged. The first snapshot and resets also use only last usage, never inherited history. Event timestamps select the month, while prior-month snapshots establish baselines. Malformed or unrecognized counters, missing contexts, resets, incomplete lines and scan caps stay partial. Delta-only events dedupe by session/turn/timestamp/counters; without a provider generation ID, distinct timestamps cannot prove whether identical delta-only events are replays. Local records do not change provider totals.

Most recorded tokens uses known calendar-month source totals in token units, separately from Model tokens, which uses only identified model token counters. Partial, missing and stale evidence qualifies the available result rather than erasing it. Source and model interaction summaries give leaders within each real action unit; they never compare turns, replies, events and requests as identical. Known zero is retained and ties list all leaders. Model tokens do not require calls, count equality or a known price; unknown account tokens are never assigned to a model. The observed model list retains the evidence and its units. Plot scales are separate per activity unit, including the desktop Model mileage list. Compact lists select one model from each activity unit in turn before taking more from any unit, so a large earlier unit cannot crowd out Codex. Desktop rows identify local device-only partial scope without global numeric ranks. Cost and allowance metric definitions are unchanged; token-derived local usage value is explicitly partial.
